# ZETTA-ZONE — Screen v1

Отдельный тест экранной области, 29.10.2026. Никакие файлы каталога и лаборатории не подключаются и не изменяются.

## Адреса

- Standalone / браузер: https://zetta-zone.github.io/screen-v1/
- Fullscreen: https://zetta-zone.github.io/screen-v1/full/

## Проверка

1. На iPhone открыть первую ссылку отдельно в Safari и Chrome. Снять показания при раскрытых панелях. Включить «Тест прокрутки страницы», провести вверх/вниз и сравнить диапазон высоты. Выключить этот тест перед остальными проверками.
2. Через Safari: «Поделиться» → «На экран Домой». Если предлагается «Открывать как веб-приложение», включить. Запускать со значка **ZZ Standalone**, а не из вкладки. Проверить, что режим **Standalone**, адресная и нижняя браузерная панели исчезли. Системные часы и жестовая полоса проверяются отдельно.
3. На Android открыть первую ссылку в Chrome → «Установить приложение» / «Добавить на главный экран». Если доступна встроенная кнопка установки, можно использовать её. Запустить установленное приложение: ожидается Standalone. Названия пунктов зависят от версии браузера.
4. Вторую ссылку на Android открыть именно в Chrome, установить как отдельное приложение **ZZ Fullscreen**. У вариантов разные manifest id, start_url и scope. Сам переход по ссылке НЕ переключает режим уже установленного PWA. Если после запуска показан Browser, это браузерный ярлык/вкладка; если Standalone — fullscreen не применился. Возможность отдельной установки определяется Chrome и политикой устройства.
5. В каждом режиме проверить портрет и альбом, внешнюю рамку, все три кнопки снизу. Каждая должна увеличить собственный счётчик. Геометрическая проверка кнопок не определяет системные наложения — реальные нажатия обязательны.
6. Отдельно проверить «Запрос Fullscreen API»: ошибка выводится на странице. Этот API не равен display: fullscreen установленного приложения.
7. В «Измерения и отчёт» указать модель, ОС, браузер и видимость системных панелей; нажать «Копировать отчёт». Если копирование недоступно, появится поле для ручного копирования. Есть системное меню «Поделиться». Ничего не отправляется автоматически.

Для сравнения панелей начинайте сеанс без клавиатуры и масштабирования. «Сбросить диапазон» очищает накопленный диапазон и журнал. Измерения в CSS px, не в физических пикселях. Высота может меняться также из-за клавиатуры, поворота и масштаба.

## Поддержка и ограничения

- Browser: сайт получает доступную область вкладки, не управляет содержимым адресной и нижней панели Safari/Chrome. Динамические значения visualViewport, innerHeight, 100dvh/100svh/100lvh показаны в отчёте.
- iPhone PWA: standalone убирает интерфейс браузера. Строка статуса, вырезы и жестовая область принадлежат iOS. viewport-fit=cover и safe-area-inset-* позволяют оформить доступную сайту область с безопасными отступами; они не гарантируют возможность рисовать под системной строкой на любой версии iOS. Устаревающий black-translucent намеренно не используется. Safe area 0 не означает отсутствие системной полосы: ОС может уже выделять под неё место вне области страницы.
- Android PWA: standalone убирает браузерные панели; fullscreen в отдельном манифесте запрашивает максимальную область. Возможны fallback в standalone и возвращение системных элементов жестом. Окончательное поведение проверяется на устройстве.
- Визуальные полосы показывают только безопасные отступы, сообщённые браузером; скрипт не может читать системный интерфейс за пределами страницы.

## Изоляция

Все ресурсы локальны внутри screen-v1/. Service Worker регистрируется только в /screen-v1/, обработка запросов ограничена этой папкой, удаление кешей — префиксом zz-screen-v1-. Корневой Service Worker не создаётся. Существующие каталоги, данные, стили и страницы не трогаются. У теста noindex,nofollow. При публикации ZIP необходимо сохранить папку screen-v1 целиком.

## Проверено до публикации

- Синтаксис app.js и sw.js, JSON обоих манифестов, существование локальных ресурсов.
- В удалённом настольном Chrome: загрузка макета, режим Browser, измерение видимой области, три нижние кнопки (3/3). Fullscreen API в этом окружении отклонён, страница отобразила отказ.
- Это не результат тестов реального iPhone или Android. Такие результаты ещё не получены; диагностический отчёт предназначен для их сбора.
